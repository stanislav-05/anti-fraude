# anti-fraud

Обработка CDR-записей коммутатора.
Данные: 471 файл `CDR_*.cdr` за 1–5 октября 2026, около 2,35 млн записей.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Положите файлы `*.cdr` в `data/raw/` (в git они не попадают).

## Запуск

```bash
python -m src.pipeline             # всё сразу: очистка -> признаки -> EDA -> скоринг -> граф -> риск звонков
```

Или по шагам:

```bash
python -m src.preprocess           # data/raw -> data/processed/calls.parquet
python -m src.features             # -> data/processed/features.parquet
python -m src.eda                  # -> reports/eda/*.csv, *.png
python -m src.scoring              # -> answer.txt, reports/candidates.csv
python -m src.graph                # -> reports/graph/*.csv, data/processed/groups.parquet
python -m src.call_risk            # -> data/processed/call_scores.parquet, reports/call_cards.md
python -m src.call_risk --number 0252432858   # карточки звонков одного номера
python -m src.model                # -> data/processed/ml_scores.parquet, reports/ml/
pytest -v                          # тесты
```

Результаты:

| Файл | Что внутри |
|---|---|
| `data/processed/calls.parquet` | чистые записи, флаги исправлений `fix_*` / `warn_*`, производные поля |
| `data/processed/quarantine.parquet` | строки, которые нельзя однозначно исправить: файл, номер строки, исходный текст, причина |
| `data/processed/quality.csv` | сколько строк затронуло каждое правило, метрики проверки |
| `data/processed/features.parquet` | признаки, одна строка на номер (индекс `number`) |
| `data/processed/features_description.csv` | описание каждого признака |
| `reports/eda/` | таблицы и графики EDA |

Интерактивно EDA удобнее смотреть в `notebooks/02_eda.ipynb` (`jupyter notebook`).

## Признаки по номерам

Номер A — инициатор вызова во всех типах записей, B — получатель, C — куда B переадресовал.

| Группа | Признаки |
|---|---|
| объём | `n_out`, `uniq_b`, `repeat_share`, `n_in`, `uniq_a`, `in_out_ratio` |
| длительность | `dur_mean`, `dur_median`, `dur_p90`, `share_dur0`, `share_le2`, `share_short`, `share_long`, `share_dur_missing` |
| окна | `peak_5m`, `peak_15m`, `peak_1h`, `peak_24h`, `max_calls_day` |
| ритм | `active_days`, `active_hour_slots`, `calls_per_active_hour`, `span_hours`, `gap_median`, `share_gap_le60` |
| время суток | `share_night`, `share_workhours`, `share_weekend`, `hour_entropy` |
| охват | `n_b_codes`, `n_b_operators`, `share_b_city` |
| связи | `callback_share`, `share_forward`, `n_forwarded`, `n_as_forward_target` |
| SIM | `n_imsi`, `numbers_per_imsi_max` |
| номер | `operator`, `is_city`, `unknown_code` |

Пропуск (NaN) в доле = «не применимо» (например, у номера без исходящих). Полное описание — в `features_description.csv`.

## Формат записи

Поля через `;`, без заголовка: тип (01 вход / 02 исход / 03 переадресация), IMSI абонента A,
номер A, номер B, начало `ГГГГММДДЧЧММСС`, длительность в секундах, номер C (для 03).
Номера — 10 цифр **строкой**: у Альфы коды начинаются с нуля.

## Правила очистки

| Проблема | Что делаем | Флаг / причина |
|---|---|---|
| больше 7 полей | берём первые 7 | `fix_extra_fields` |
| 6 полей | восстанавливаем по типу записи | `fix_missing_field` |
| меньше 6 полей | карантин | `too_few_fields` |
| код страны +7/8, пробелы, дефисы в номере | срезаем до 10 цифр | `fix_country_code` |
| номер A / B не восстанавливается | карантин | `bad_number_a` / `bad_number_b` |
| A = B | карантин | `self_call` |
| дата `ГГГГ-ММ-ДД ЧЧ:ММ:СС` | разбираем | `fix_date_format` |
| битая дата | берём дату из предыдущей строки файла* | `fix_date_imputed` / `bad_date` |
| тип `1`/`2`/`3` | добавляем ноль | `fix_type_zero` |
| тип-мусор (`AA`, `00` …) | выводим: есть C → 03, есть IMSI → 02, иначе 01 | `fix_type_inferred` |
| длительность нечисловая / < 0 / > суток | пусто, строку оставляем | `fix_bad_duration` |
| дробная длительность | округляем | `fix_duration_rounded` |
| неверный IMSI | пусто | `fix_bad_imsi` |
| неизвестный код оператора | оставляем, помечаем | `warn_unknown_code` |
| точный дубль | удаляем | `duplicates_removed` в отчёте |

\* Корректно, только если записи в файле идут по времени: смотрите `files_sorted_share` в `quality.csv`.
Отключить: `python -m src.preprocess --no-impute-dates`.

Нулевая длительность не означает «неотвеченный»: статуса ответа в данных нет.

## Скоринг

Каждое правило — понятный факт о номере с баллами (`src/scoring.py`, список `RULES`).
Риск = сумма баллов в пределах 0–100; объяснение — сработавшие правила с баллами.

| Правило | Баллы |
|---|---|
| ≥ 300 звонков за час | +40 |
| ≥ 50 звонков за 5 минут | +15 |
| ≥ 300 разных получателей, повторов ≤ 5% | +15 |
| ≥ 30% звонков до 10 с | +10 |
| никто из получателей не перезвонил | +10 |
| профиль робота: ≥ 300 разных получателей, медиана ≤ 20 с, перезвонов нет | +35 |
| wangiri: ≥ 90% звонков короче 10 с у ≥ 300 получателей | +45 |
| круглосуточно: ≥ 4 дней, ночью ≥ 10% | +35 |
| ≥ 3 разных SIM у номера | +70 |
| одну SIM делят несколько номеров | +10 |
| график офиса: ≥ 3 будних дня, ни ночью, ни в выходные | −45 |
| ≥ 10% получателей перезванивают (кроме wangiri) | −20 |

Уровни: **высокий** (≥ 70) — в ответе; **проверка** (40–69) — только с `--include-review`; **низкий**.
Автоблокировки нет: результат — рекомендация оператору, а не решение.

## Графовый анализ

`src/graph.py` проверяет «веер» из ТЗ — группу номеров, которая по одному шаблону
обзванивает непересекающиеся списки:

- **SIM:** граф «номер — IMSI» (NetworkX), компоненты связности = номера, работавшие с общими SIM;
- **получатели:** для каждой пары кандидатов — доля общих номеров B (коэффициент Жаккара);
  `overlap_share` по паттерну около 0 означает, что база поделена между номерами;
- **расписание:** сколько номеров каждого паттерна работало в каждый день;
- **группы:** компоненты графа (общая SIM или Жаккар ≥ 0,3) → `reports/graph/groups.csv`.

## Риск отдельного звонка

`src/call_risk.py`: риск звонка = риск номера A + признаки самого звонка
(сброс до 2 с, короткий звонок, ночь, получатель ни разу не звонил этому номеру,
перезвон жертвы на номер wangiri, номер из связанной группы). Результат — карточка, как в ТЗ:
факторы с баллами, рекомендация и «автоблокировка: нет».

## Защита

- `src/policy.py`: автоблокировка выключена, белый список экстренных номеров (112, 101–104, 01–04)
  и доверенных номеров из `data/whitelist.txt` проверяется до модели;
- `tests/test_policy.py`: ответ на вопрос «что будет, если заблокировать скорую»;
- `docs/DEFENSE.md`: контроль ложных срабатываний, ограничения метода.

## ML-модели

`src/model.py` (`python -m src.model`). Разметки нет, поэтому метки — псевдометки от правил:
«высокий» = 1, активные номера (≥ 10 исходящих) с риском < 20 = 0, «серые» в обучение не идут.

- **CatBoost `full`** — все признаки: ранжирование и SHAP-объяснение, «второе мнение» к правилам;
- **CatBoost `independent`** — без признаков, на которых построены правила: проверяет,
  видна ли схема не только через пороги правил;
- **проверка по дням** (если есть `calls.parquet`): признаки и метки пересчитываются отдельно
  за 1–3 и 4–5 октября, модель учится на первом периоде, тест — на втором, где номера-залпы новые;
  иначе — 5-кратная кросс-валидация;
- **Isolation Forest** (scikit-learn) — аномалии среди номеров с ≥ 20 исходящими, без меток.

Модель не меняет `answer.txt`. Результаты: `data/processed/ml_scores.parquet`,
`reports/ml/metrics.json`, `reports/ml/disagreements.csv`, `reports/ml/anomalies.csv`.
